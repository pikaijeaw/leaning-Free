A: Two of them. First, the root user. That's the login you made the account with. It can do everything. Give it multi factor authentication, then leave it alone for daily work.
B: And second?
A: Apps get roles, not keys. Picture an app on a server that reads files from S3. The weak way puts an access key in the app's config file. The better way attaches a role to the server, with temporary credentials, and only permission to read, not delete.
B: So a leaked config file leaks nothing useful.
A: Exactly. Three of the five pages on access teach roles over stored keys. None disagree.
